# Auditar o modelo de falha em 14 dias

Consulte [o alinhamento com a proposta](../ALINHAMENTO_PROPOSTA.md), [as premissas do simulador](../PREMISSAS_SIMULADOR.md), [a auditoria da disciplina](../AUDITORIA_ML.md) e [o guia de ML](../../applications/ml/README.md). Para uma mudança de premissa, confira o critério da T5b no [backlog](../O_QUE_FALTA.md).

1. Confira o que mudou em [premissas_parque.json](../../applications/simulador/premissas_parque.json), [parque.py](../../applications/simulador/parque.py) ou no treino. Identifique os parâmetros calibrados com dados da Emlurb e as premissas adotadas pelo grupo. Rastreie a origem do conjunto usado na execução escolhida. A tarefa é prever falha em `(t, t+14 dias]` por luminária usando dados simulados. Dados da Emlurb calibram o simulador. O modelo de risco por bairro tem avaliação própria.
2. Em [parque_features.py](../../applications/ml/src/parque_features.py) e [treinar_falha.py](../../applications/ml/src/treinar_falha.py), confira se as features usam apenas informações disponíveis em `t`, se os rótulos têm a janela completa e se as partições seguem o split temporal 70/15/15 com separação de 14 dias. Confira o walk-forward do Optuna dentro do treino e se a seleção, a calibração e o ajuste de limiar preservam o teste final.
3. Confira [os metadados versionados](../../applications/ml/models/metadados_falha.json) e, quando disponível, a execução correspondente no experimento `falha_14d` do MLflow. Compare as PR-AUC de validação e teste do modelo com a regra simples e a baseline aleatória estratificada no mesmo conjunto. Registre Brier, precision@k e recall@k quando disponíveis. Compare a PR-AUC do cenário de robustez com a do teste padrão e registre a prevalência de falhas quando disponível. Identifique a execução pela data ou pelo ID para distinguir metadados, notebook e treino local.
4. Em `applications/`, rode `docker compose run --rm --no-deps api python -m pytest tests/test_parque_e_features.py tests/test_pipeline_e_api.py -q` quando a imagem estiver disponível. Para mudanças em Python, rode também a suíte completa conforme [CLAUDE.md](../../CLAUDE.md). Use os testes como evidência para as regras que eles cobrem e confira as demais no código e nos artefatos. Se a tarefa incluir regeneração do parque ou treino, siga o guia de ML e registre quais artefatos foram atualizados.

Entregue os achados com arquivo e linha ou ID de execução, as métricas observadas, a origem dos dados e as limitações. Identifique o que foi inspecionado, o que os testes cobriram e o que depende de uma execução. Para alterar valores de premissas na T5b, use os valores aprovados pelo grupo.
